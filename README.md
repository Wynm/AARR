# AARR — آفاق الربح الرقمي 🚀
### نظام تشغيل تجاري رقمي متكامل للمستقل المغربي (منتج + واجهة + قاعدة بيانات + عمليات)

> **AARR** (آفاق الربح الرقمي — Afâq Arrabḥ al-Raqmī) هو مشروع تجاري رقمي واقعي مبني حول منتج واحد قوي:
> **«حزمة الذكاء الاصطناعي للمستقل المغربي»** — دليل عملي بالعربية + 12 قالباً جاهزاً + خطة 30 يوم.
> الهدف: بيع رقمي شرعي وبتوافق مع القوانين، وبأتمتة قصوى للعمليات بأدوات مجانية/شبه مجانية.
>
> ⚠️ **تصريح أمانة علمية:** لا يوجد دخل «مضمون» في أي منتج أو نظام. هذا المشروع يبني الأصل والمنظومة؛
> النتائج المالية تعتمد على التنفيذ والتسويق وصبر صاحبه. كل الأرقام في الوثائق هي **أهداف** لا وعود.

## 3) التشغيل المحلي (بدون أي تبعيات)

المتطلبات: `python3` أو `node ≥ 18`.

```bash
# الطريقة 1: بايثون
python3 -m http.server 8080 --directory site --bind 0.0.0.0
# الطريقة 2: نود
node -e "const http=require('http'),fs=require('fs'),path=require('path');const root='site';http.createServer((req,res)=>{let p=path.join(root,decodeURIComponent(req.url.split('?')[0]));if(p.endsWith('/'))p+='index.html';fs.readFile(p,(e,d)=>{if(e){res.writeHead(404);return res.end('404')}res.end(d)})}).listen(8080,'0.0.0.0')"
```
افتح: `http://localhost:8080/` (محلياً) — و`https://<port>-<sandboxId>.e2b.app/` في معاينة Arena.

### كيف يتصل الموقع بقاعدته؟
- النموذج يكتب عبر PostgREST بالمفتاح **anon العام** في `site/config.js`.
- RLS تسمح فقط بـ `INSERT` بشرط `consent = true` على `leads` — لا قراءة، لا تعديل، لا حذف.
- إن تعذر الوصول (انقطاع إنترنت/شبكة): تُحفظ النسخة محلياً في `localStorage` ويمكن تصديرها CSV من لوحة العمليات — **لا تضيع أي معلومة عميل**.

### لوحة العمليات
`http://localhost:8080/dashboard.html` — tabs: نظرة عامة | العملاء | الدفتر المالي | خط الأنابيب | مؤشرات الإطلاق.
كل شيء يعمل محلياً. للمزامنة الحقيقية: الصق **service_role** في مربع «المزامنة» (يُحفظ في ذاكرة الجلسة فقط).

## 4) النشر على الإنترنت (مجاني، 5 دقائق)

اختر واحداً (الأسهل أولاً):

**أ) GitHub Pages:** Settings → Pages → Deploy from branch `main` + `/ (root)` ثم اجعل `site/` هو الجذر… أو انقل محتويات `site/` إلى جذر فرع `gh-pages`. الأفضل: استخدم Netlify.

**ب) Netlify (مستحسن — سحب وإفلات):**
1. انسخ مجلد `site/` (كل ما بداخله) إلى Netlify Drop، أو اربط المستودع مع «Base directory: `site`، Publish directory: `site`».
2. لا حاجة لأي متغيرات بيئة — كل شيء ثابت؛ المفتاح anon عام عمداً ومحمي بـ RLS على الخادم.

**ج) Cloudflare Pages:** نفس الشيء (لا يوجد build، دليل النشر = `site`).

**الدومين:** اضبط `www.yourdomain.com` → الواجهة — واحتفظ بنسخة من الروابط في Notion/المستودع.

## 5) ماذا تفعل قبل الإطلاق (17 خطوة مرتبة)

1. ✅ افحص الموقع محلياً (يُعمل) ولقطة المعاينة تعمل.
2. ⏳ **أنشئ حساب دفع**: Payhip أو Gumroad (بطاقات دولية) أو CMI (السوق المغربي — يحتاج مقاولة).
3. ⏳ ضع الرابط في `site/config.js` مكان `buyUrl` (مثال: `https://payhip.com/buy?link=XXXX`).
4. ⏳ حمّل الدليل بصيغة PDF إلى Payhip (Product → File).
5. ⏳ أرسل بريداً اختبارياً لنفسك عبر زر الشراء (تجربة كاملة من الشراء حتى استلام الملف).
6. ⏳ **CNDP**: سجل معالجة المعطيات الشخصية للعملاء المحتملين (المغرب: القانون 09-08 + قانون 05-20). استشارة مجانية عبر موقع cnia.ma. *هذا إجراء قانوني لا تمنعه أي أداة — خذ 30 دقيقة فقط.*
7. ⏳ أضف البريد الرسمي للدعم وتحديثه في `site/config.js` وNotion.
8. ⏳ صوّر/احصل على 3 شهادات/توصيات حقيقية (حتى من زملاء تطوعوا لمراجعة الدليل) — لا تخترع شهادات أبداً.
9. ⏳ لينكدإن: حدّث العنوان، انشر بوست الإطلاق (قالب جاهز في Gmail مسودات / Notion).
10. ⏳ انشر في المجموعات: «المغرب للابتكار الرقمي»… القاعدة: قيمة أولاً، عرض بعدها.
11. ⏳ فعّل Google Calendar cadence (محتواه موجود: تقويم AARR الأسبوعي) — التزم به 90 يوماً.
12. ⏳ GitHub: اجعل المستودع خاصاً أو عاماً حسب رغبتك؛ أضف أسرار `SUPABASE_URL` و`SUPABASE_SERVICE_KEY` لتفعيل لقطة KPI الأسبوعية.
13. ⏳ راجع سياسة الاسترجاع في صفحة الهبوط (14 يوم) وتأكد أن Payhip تسمح بذلك.
14. ⏳ اطبع بطاقة عمل / QR يشير إلى الموقع — مفيدة في كل مرة يجتمع فيها مستقلون.
15. ⏳ عاين الموقع من هاتف حقيقي (زر CTA بارز، النموذج سهل).
16. ⏳ اضبط Google Analytics 4 (اختياري) مع موافقة الكوكيز، أو استعمل Plausible/Umami مستقل.
17. ⏳ سجّل كل شيء في Linear (المهام موجودة) — انسخ رابط المستودع والموقع للعميل/الشريك.

## 6) التشغيل وقت «التوقف» أو «العطل» (Runbook الحوادث)

| العَرَض | التشخيص خلال دقيقة | الإجراء |
|---|---|---|
| الموقع لا يفتح | `curl -I https://موقعك` — هل DNS/404/502؟ | مشكلة استضافة → أعد النشر (Netlify «Deploys → Trigger deploy»). لا DNS → أصلح CNAME. |
| النموذج لا يحفظ (رسالة «حُفظت محلياً») | انقطاع إنترنت الزائر أو Supabase متوقف | لا تتدخل فوراً — البيانات في localStorage للزائر نفسه؛ لوحة العمليات تعرضها عند نفس الجهاز. تحقق من حالة Supabase عبر dashboard الخاص بالمشروع (`rdendsijoowivydpvqho` → Health). |
| أخطاء 401/403 من Supabase | مفتاح anon قديم أو RLS تغيّرت | أعد نشر `config.js` بالمفتاح الحالي من «Project Settings → API Keys». طابَق `supabase/migration.sql`. |
| الدفع لا يصل → الدليل لا يُسلم | Payhip/Gumroad معطّل | افحص صفحة الحساب هناك ← ثم «Runtime check» في البريد. جهّز PDF يدوي الإرسال مؤقتاً (الملف في `product/`). |
| Gmail/Calendar لا يتزامن | صلاحيات OAuth | افصل التطبيق من إعدادات Google ← أعد توصيله من Arena. اللوحة لا تتأثر. |
| لوحة العمليات بياناتها اختفت | مسح cache/localStorage | استرجع من آخر «نسخ احتياطي JSON» نزّلتها. لا توجد نسخة على الخادم إلا إذا زامنتها بمفتاح الخدمة في الجلسة. |
| النشرة البريدية لم تُرسل | (لا يوجد إرسال تلقائي أصلاً — عن قصد) | Gmail ← المسودات `AARR —` ← راجع وأرسل يدوياً بعد التأكد من الموافقة. |
| كل شيء يعمل لكن لا عملاء | (مشكلة تسويق، لا عطل) | راجع cadence المحتوى — قارن أرقام `kpi_snapshots` أسبوعاً أسبوعاً؛ إن ركدت 2 أسابيع: غيّر الرسالة لا المنتج. |

**احترام الخصوصية وقت الحادث:** لا ترسل نسخة احتياطية تحتوي إيميلات العملاء إلى أي وسيط (لا واتساب، لا ملفات مشتركة عامة). النسخ الاحتياطية تُخزّن في مجلد AARR/Ops الخاص على Dropbox فقط.

## 9) الأمان والامتثال (اقرأها قبل أي شيء)

- ✅ **لا توجد أسرار في الكود:** المفتاح العام `anon` آمن عمداً — RLS هي حارس الباب. المفتاح `service_role` و`db_pass` لا يظهران إلا في GitHub Secrets أو داخل Supabase.
- ✅ **الموافقة أولاً:** كل بيانات يجمعها الموقع مشروطة بـ `consent = true` (رفض = لا تُحفظ شيئاً).
- ✅ **لا سبام:** الرسائل القالبية تُرسل شخصياً وبنسبة قيمة/عرض معقولة (4/1) — لا قوائم بريدية مشتراة، لا إرسال جماعي.
- ✅ **خصوصية:** CNDP (قانون 09-08) قبل أول عميل حقيقي. لا تشارك بيانات العملاء مع أي AI عام — استعمل نسخة تجارية أو حذف المعطيات.
- ✅ **الملكية الفكرية:** منتجات الذكاء الاصطناعي في الحزمة قابلة للاستعمال التجاري عادة — يلتزم المشتري بشروط الأدوات؛ المستندات والقوالب من إنتاج مشروع AARR.
- ✅ **التسويق:** لا ادعاءات أرباح، لا شهادات مخترعة، التسعير واضح قبل الدفع.
- ✅ **الاسترجاع 14 يوم** مع احترام قرار العميل بلا جدال (أخلاقي + تسويق شفهي ممتاز).
- ⚖️ هذا الملف ليس استشارة قانونية ولا ضريبية. للعقود الكبيرة أو التسجيل كمقاول ذاتي، استشر مختصاً.
